AI Pre-Flight

A pre-deployment checklist for agentic AI apps — the controls that turn "the model did something" into something you can defend, trace, and shut off. Run it once per project, before the first real deploy.

Origin — synthesized while shipping agentic apps in regulated work Scope — 6 sections, 30 checks Storage — your checks save locally, in this browser only
Running the checklist

How to work through it

  1. 1

    Note the organisation context — ORG-tagged items need your current employer's equivalent (risk gate, identity, catalog). Unsure if the project touches a regulated process? Ask before assuming autonomy is uncapped.

  2. 2

    Investigate before proposing — check the actual codebase for current status per item; don't take a self-report at face value.

  3. 3

    One item at a time — this is a big lift for a new project. Confirm scope, get sign-off on nontrivial choices, then implement.

  4. 4

    Report status plainly — done, partial, or missing, with a file reference once code exists. A named, accepted gap is honest; a silent one isn't.

  5. 5

    Never mark an item done without evidence — a specific file or function implements it, exercised, not "an LLM would generally handle this."

1

Plan & Classify

decide what you're building, and how much control it needs
0/5
  • 1.1

    Define one clear goal & scope. State a single objective — task-based, process-based, or goal-based. Tight scope is the cheapest control available; resist creep now rather than guardrailing it later.

  • 1.2

    Classify the autonomy level, L1–L5. Cruise control → adaptive assist → supervised autopilot → geofenced self-driving → full autonomy. Pick the lowest level that still does the job; escalate only with justification.

  • 1.3ORG

    Determine regulated-environment applicability. Clinical, financial, safety-critical, legal? Cap autonomy per the current org's regulated cap and keep a human in the loop on any critical LLM decision there.

  • 1.4ORG

    Request a formal risk assessment before rollout. Use the current org's risk gate. No such gate yet? Note it as a real gap, not a skip — before pilot, not after.

  • 1.5ORG

    Check what rules already bind this work. AI usage policy, data handling policy, HIPAA/GDPR or industry-specific rules relevant to the data the agent touches.

2

Build & Ground

configure the agent on solid, well-described foundations
0/5
  • 2.1

    Write a clear system prompt. Role, task, output format, available tools — explicit. Prefer a structured output schema over free text where correctness matters. Ground it in versioned sources, not ad hoc inline facts.

  • 2.2

    Name tools accurately. Tool names often matter more than descriptions for correct selection — treat naming as a first-class design decision.

  • 2.3ORG

    Assign a clear owner and identity. A named human, reachable, responsible for the agent's lifecycle. Target the org's identity platform where one exists; a named owner in the repo is the floor everywhere else.

  • 2.4

    Create an Agent Card. A machine-readable descriptor of scope, owner, autonomy level, and known limitations — discoverable without reading all the code.

  • 2.5

    Verify grounding data is complete and reliable. Stale docs or an incomplete corpus are the most common cause of bad output — rule this out before blaming the model.

3

Test & Validate

prove it works, and fails, safely, before anyone relies on it
0/4
  • 3.1

    Conduct eval-driven testing. Happy path, edge cases, failure cases — defined explicitly, with documented coverage a reviewer can trust without re-deriving it.

  • 3.2

    Validate accuracy and bias. Measure against real ground truth, not spot checks. Check whether output is systematically worse for some input subpopulation — and re-check after any material change.

  • 3.3

    Test failure and escalation behavior. When a step fails, does it self-correct within bounds, or escalate to a human? Confirm the guardrails hold under a real failure, not just the success path.

  • 3.4

    Separate deterministic from probabilistic logic. Cap the LLM parts at a conservative autonomy level in regulated contexts; don't let deterministic business logic quietly become model-decided.

4

Govern & Oversee

wire in guardrails, visibility, and safety controls
0/4
  • 4.1

    Build in human-in-the-loop checkpoints. Oversight never reaches zero on anything high-stakes. An AI-proposed change is never auto-committed — it needs an explicit human "Apply."

  • 4.2

    Enable monitoring and call tracing. End-to-end tracing of calls, tokens, cost, and outcome per invocation — reviewable after the fact, not just while watching it run.

  • 4.3

    Address AI security explicitly. Confidentiality, integrity, availability — including prompt injection by name. Least privilege: restrict the agent to only the tools it actually needs.

  • 4.4

    Set content-safety and cost controls. Guard against inaccurate output reaching a human as if authoritative. A kill switch and a budget cap, with real spend visibility.

5

Document, Train & Deploy

make it usable, discoverable, and accountable
0/5
  • 5.1

    Prepare user guidance. How to use it, its limits, when to escalate, who owns it — part of making the capability safely discoverable, not just usable.

  • 5.2

    Confirm operator training wherever the agent touches a regulated process — operators need to understand its limits, not just have read a README once.

  • 5.3ORG

    Register in a shared, discoverable catalog if the current org names one. Skip cleanly if it genuinely has none — don't invent a registry that doesn't exist.

  • 5.4

    Final sign-off and owner accountability. The named owner records a dated go/no-go, confirming every gate above actually passed. Append new decisions as scope grows — never overwrite an old one.

  • 5.5ORG

    Know where to get help. Name the specific escalation path — a consult channel, a governance team, an internal community — per the current org.

6

Golden Standard & Guardrails

the concrete technical patterns behind §4
0/7
  • 6.1

    Kill switch. One flag, checked before rate limiting or budget, in every path that calls the model. Genuinely accessible and actually tested — not just theoretically present.

  • 6.2

    Rate limit + daily cost budget. Enforced server-side, never client-side. Size the cap to the shared credential actually in use — especially once fire-and-forget jobs remove the natural human throttle.

  • 6.3

    Agent drift tracking. Detect degrading output quality over time — a rising defect severity or remediation-cycle count — rather than silently absorbing it. Detection triggers a human decision; correction stays a human call.

  • 6.4

    Memory and amnesia options. Be explicit about what the agent remembers, across turns and sessions, and for how long. No cross-session memory unless it was a deliberate decision with its own retention story.

  • 6.5

    Traceability / audit trails. Metadata-only records — timestamps, status, cost, tokens, decision outcomes — with a defined retention period. Behavior should be fully reconstructable after the fact.

  • 6.6

    Cyber security guardrails. Untrusted input treated as data, never instructions. A CSP restricting egress to same-origin. Zero client-side credentials — every privileged call goes through a server-side relay.

    Prompt injection

    Flag suspicious phrases ("ignore previous instructions") for human review, not silent auto-block — false positives on legitimate content are expected. Any AI-proposed write needs explicit human approval first.

    Data exfiltration

    CSP allowlist blocks injected code from calling out externally. Never expose an upstream credential client-side. Audit records stay metadata-only. Prefer zero third-party script dependencies.

    Unauthorized access & least privilege

    Name what access control actually is today — a shared secret is a legitimate, honestly-documented stopgap for a small pilot, with a named real fix before broader rollout. Scope bindings per-function where the platform allows it.

  • 6.7

    Document the full deployment architecture. Models, endpoints, data pipelines, infrastructure, and dependencies — in one place, not scattered across tribal knowledge.

Not an official standard from any organization — a personal working synthesis, meant to drive real engineering work rather than get filled in for its own sake. Full guidance, org-profile mechanics, and reference implementation pointers live alongside this page in SKILL.md.
